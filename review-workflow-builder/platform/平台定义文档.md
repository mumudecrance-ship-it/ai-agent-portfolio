# FlowBench 工作流定义规范（平台定义文档）

> 工作流定义为原生 JSON。本文档是节点 schema 的唯一权威来源，skill 的 `references/platform-nodes/` 节点库与本文档同源——**节点方案中的每个字段必须能在本文档找到出处，杜绝想象字段。**

## 1. 顶层结构

```json
{
  "app": {"name": "应用名"},
  "variables": [{"name": "review_text", "type": "string", "required": true, "example": "..."}],
  "graph": {
    "nodes": [{"id": "唯一id", "type": "节点类型", "title": "显示名", "config": {}}],
    "edges": [{"source": "上游id", "target": "下游id", "source_handle": "分支句柄(可选)"}]
  }
}
```

约束：恰好 1 个 `start` 节点；至少 1 个 `end` 节点；边的两端必须存在；分支类节点（if_else / question_classifier）的出边必须带 `source_handle`。

## 2. 变量引用语法

`{{#节点id.字段.子字段#}}`。首段可为 `inputs`（开始节点输入）或任意已执行节点的 id。在 `iteration` 节点内部额外可用 `{{#item.xxx#}}`。
纯引用（整个值只有一个引用）保留原始类型（数组/对象/数字）；混在文本里则转为字符串拼接。

## 3. 节点类型（12 类）

| type | 名称 | config 字段 | 输出字段 |
|---|---|---|---|
| `start` | 开始 | 无（输入由顶层 variables 定义） | `inputs` |
| `end` | 结束 | `outputs`: {输出名: 引用} | `outputs` |
| `llm` | LLM | `prompt`: 含变量槽位的提示词 | `text`(原文), `json`(可解析时) |
| `knowledge_retrieval` | 知识检索 | `query`, `top_k`, `product_id`(可选,限定范围) | `result`(命中列表,含score), `count` |
| `if_else` | 条件分支 | `conditions`: [{left,op,right}], `logic`: and/or；op ∈ ==,!=,contains,not contains,>,<,>=,<=,empty,not empty | `result`(bool)；分支句柄 `true`/`false` |
| `question_classifier` | 问题分类器 | `input`, `classes`: [{id,name,keywords,default?}] | `class`, `class_name`；分支句柄=class id |
| `code` | 代码执行 | `inputs`: {名:引用}, `code`: Python 片段（读 `inputs`，给 `outputs` 赋 dict） | `outputs` 的键 |
| `http_request` | HTTP 请求 | `method`, `url`, `body`, `timeout` | `status_code`, `body` |
| `iteration` | 迭代 | `input`(列表引用), `mode`: template/llm, `template` 或 `prompt` | `result`(列表), `count` |
| `variable_aggregator` | 变量聚合 | `variables`: [引用], `strategy`: first_not_null / merge_list | `output` |
| `parameter_extractor` | 参数提取 | `input`, `parameters`: [{name,type,pattern?,max_len?}] | 各参数名 |
| `template_transform` | 模板转换 | `template`: 含变量槽位的文本 | `output` |

## 4. 调度接口（S7 脚本调用）

| 接口 | 说明 | 返回 |
|---|---|---|
| `POST /apps/imports` | body: `{definition}`；不合法返回 422+错误清单 | `{imported, app_id}` |
| `POST /apps/{id}/publish` | 发布（运行前必须发布） | `{published, version}` |
| `POST /workflows/run` | body: `{app_id, inputs}` | `{run_id, status, outputs, error, elapsed_ms}` |
| `GET /workflows/run/{id}` | 回读，含 `node_runs`（逐节点 status/output/error/耗时） | 完整 run 记录 |

status ∈ `succeeded` / `failed`。失败时 `node_runs` 中恰有一个 `failed` 节点，`error` 给出节点级定位。

## 5. 评价域 mock 业务接口

| 接口 | 说明 | 返回口径 |
|---|---|---|
| `POST /mock/svc/same-image` | 同图识别，body: `{image_urls}` | `result`: 0非同图/1疑似/2同图 |
| `POST /mock/svc/ai-image` | AI生图识别 | `result`: 0非AI/1AI |
| `POST /mock/svc/irrelevant-image` | 无关图识别 | `result`: 0相关/1疑似/2无关 |
| `POST /mock/svc/sensitive-words` | 敏感词，body: `{text}` | `{hit, words}` |
| `POST /mock/svc/ocr` | OCR | `{text}` |
| `POST /mock/item-center/detail` | 商品信息中心，body: `{product_id}` | `{product}` |
| `POST /mock/review-base/query` | 评价查询服务，body: `{product_id, limit}` | `{reviews, count}` |

错误注入：任意 mock 接口 body 加 `"__inject__": "500"` 返回 500；`"timeout"` 延迟 8 秒。用于演示失败分支与报错回读。

## 6. LLM 节点执行模式

`seed-data/platform_config.json`：`llm_mode=demo`（默认）走内置演示模式——按 `seed-data/llm_demo_outputs.json` 的规则返回确定性输出，零配置跑通全流程；填入 `api_key` 并把 `llm_mode` 改为 `api` 即切换真实模型（OpenAI 兼容接口）。
