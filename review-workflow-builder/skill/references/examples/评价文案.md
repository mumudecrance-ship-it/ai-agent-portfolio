# 复盘 · 评价文案（商品问答）文案

## 业务问题
评价发起页的引导问题靠运营手写：质量依赖个人经验、泛问题无引导力、有诱导/夸大/时效风险、词条会过时。目标自动生成中性具体可回答的引导问句，运营审核上线。

## 依赖能力
品类属性/卖点库、SKU卖点库、大家问已有数据、商品信息中心。客服侧数据曾考虑后不开放——依赖分析要接受"能力不可得"并调整方案。

## 节点结构（平台节点口径，双工作流合计 14 节点）
**基础工作流**：取商品卖点 → 逐卖点迭代 → A3 卖点语义比对(llm，与类目通用卖点判同义，cross-encoder>0.7 视为历史有同类问题) → 前置正则(parameter_extractor/code) → A4 素材筛选(llm，排除1~8/通过A~E) → A7 问句改写(llm，五原则+红线+自检) → 风险闸+运营审核(end转审)
**高优工作流**（周执行）：从高优商品的大家问/评价信号中补充候选 → 同判定改写链路

## 方法论要点
- 三个 prompt 各管一段（②单一任务的最强样本）：比对≠筛选≠改写，输出 JSON 字段约束严格、few-shot 含易混淆例
- 先正则后 prompt（①+④）：关键词能排除的不花 token
- 双工作流解耦（⑤）：日常链路与高优补充链路分开，节奏不同
- 自检+重写内置于 A7，下游还有风险闸+人审（⑥双保险）
- 验收先主观测评（合格率92.8%、单商品达标99.5%）再 AB（⑦）
