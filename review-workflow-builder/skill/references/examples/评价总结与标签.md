# 复盘 · 评价总结 + 标签

## 业务问题
评价区信息密度低，用户决策成本高。以卖点为中心生成总结（核心卖点+认同人数+买家原声），替代"从评价里总结观点"的失败路线（观点分散、与卖点对齐率仅约27%、结构不一致）。

## 依赖能力
商品信息中心（商详图/标题）、OCR（商详图→文本）、评价查询服务（高质量评价源）、评价RAG（句子分片、混合检索+rerank+时间衰减）、客服审核流、商品竞争机制。

## 节点结构（平台节点口径，9 节点）
获取商详信息(http) → OCR(http) → 卖点提取prompt(llm，TOP5可控) → 【迭代：逐卖点】找相关评价(knowledge_retrieval，占比<50%该卖点终止 if_else) → 卖点总结prompt(llm) → 评价截取prompt(llm，保留5组) → 整合成一句话prompt(llm) → 人审(end转审) → 商品竞争(传统)

## 方法论要点
- 先画靶再射箭：卖点为中心，不从评价正向归纳（③先流程后prompt 的业务版）
- 逐卖点迭代而非一把抓（②单一任务）；占比不足 50% 早停（④开销）
- 买家原声选评价官/PLUS（风险控制）；输出带引用可追溯
- 微调仅 200 条总结样本，属算法侧职责——产品保流程可行，算法保效果稳定
