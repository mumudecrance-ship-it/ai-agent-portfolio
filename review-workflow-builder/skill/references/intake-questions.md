# S1 业务四问（只问业务，不问任何技术）

> S1 只允许问业务问题。数据从哪来、有什么接口、用什么模型——那是 S2 依赖分析的事，由 skill 自己推断，用户只做确认。

## 四问

1. **解决什么业务问题，成功标准是什么？**
   追问话术：现在这件事是谁在做/没人做？做到什么程度算解决？
2. **产出给谁用，什么形态？**
   追问话术：结果是给运营看的列表、给系统消费的标签，还是给用户看的文案？谁对产出质量负责？
3. **量级与执行频率？**
   追问话术：一天/一周处理多少条？是全量跑存量，还是只处理增量？实时性要求到分钟还是到天？
4. **哪些环节的错误不可接受（人审底线）？**
   追问话术：误伤了会怎样？漏掉了会怎样？哪种代价更高？什么情况必须人来拍板？

## 产出

回答落 `01-工作流画像.md`：业务问题 / 成功标准 / 产出对象与形态 / 量级与频率 / 错误容忍与人审底线，共五段，每段 1-3 句。

## 红线

- 出现"接口""数据库""模型""并发"等字样的提问一律违规——业务方答不上来，且这本来就是拆解能力的一部分
- 一次最多补问 2 个问题；诉求里已说清的不重复问
