# 代码执行节点（code）

## 能力
- `config.inputs`: {名: 引用}，`config.code`: Python 片段——读 `inputs` dict，给 `outputs` 赋 dict
- 传统确定性逻辑全在这里做：计数、规则、交集、格式整理

## 真实 DSL 片段
```json
{"id": "final", "type": "code", "title": "综合判断",
 "config": {"inputs": {"llm": "{{#agg.output#}}", "img": "{{#same_img.body#}}"},
   "code": "v = inputs[\"llm\"] or {}\nimg = inputs[\"img\"] or {}\nlow = (v.get(\"verdict\") == 1) or (img.get(\"result\") == 2)\noutputs = {\"quality\": \"低质量\" if low else \"高质量/普通\", \"need_human\": img.get(\"result\") == 1}"}}
```

## 已知限制（真实踩坑）

- 代码在受限环境执行：**列表/生成器推导式内引用外层局部变量会 NameError**（作用域隔离），一律改用显式 for 循环
- 可用内建函数为白名单（len/str/int/float/list/dict/set/sum/min/max/sorted/range/enumerate/abs/round/any/all/zip/isinstance/bool/type），白名单外的内建不可用

## 评价域使用要点
- 质量管控功能点1/2/18（带图判断、字数、综合交集判断）全是 code，不进 LLM——传统系统更准更快且零 token 开销
- 多路判定结果的合并逻辑（取交集/优先级）写在 code 里，让规则显式可审
