# 迭代节点（iteration）

## 能力
- `config`: `input`（列表引用）、`mode`: template/llm、`template` 或 `prompt`（内部用 `{{#item.xxx#}}` 引用当前项）
- 输出 `result`（逐项结果列表）、`count`

## 真实 DSL 片段
```json
{"id": "per_sellpoint", "type": "iteration", "title": "逐卖点改写问句",
 "config": {"input": "{{#filter.json.sellpoints#}}", "mode": "llm",
   "prompt": "把卖点改写为中性问句，输出JSON{question}。\n卖点：{{#item.value#}}"}}
```

## 评价域使用要点
- 总结工作流"每个卖点分别找评价"、评价文案"逐卖点判定/改写"即此形态
- **开销警戒点**：迭代内含 LLM 时，调用次数 = 列表长度。方案必须回答：列表上限多少、能否先用传统手段/沉淀库缩短列表（亮点工作流的沉淀跳过机制就是为此）
- 批量并不省钱：并行调用总开销一致；有沉淀跳过机制时批量反而可能多花（亮点项目口径）
