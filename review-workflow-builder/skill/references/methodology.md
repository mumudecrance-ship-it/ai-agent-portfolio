# 工作流设计方法论（五条 · S6 审查清单）

> S6 逐条过审：每条给出 通过/不通过/不适用 + 证据。"不通过"清零前不得进入 S7。

## ① 能不用 AI 就不用 AI
传统系统输出更准、更快、零 token 开销。字数/带图/返回码/正则可判的，一律 code / if_else / parameter_extractor。S3 拆解期已要求每个 LLM 步骤给出"非 LLM 不可"的理由，S6 复核这些理由是否站得住。
**审查问法**：方案里每个 LLM 节点，把它换成传统判断行不行？

## ② 单节点单一任务
一个 prompt 只解决一个问题（A3 只比对、A4 只筛选、A7 只改写）。复合 prompt 输出质量不可控、不可测。
**审查问法**：有没有节点同时输出两类以上判定？

## ③ 开销意识
量级 × 调用次数 = 开销。必答：执行频率、单次处理量、迭代内 LLM 调用上限、先过滤后进模型。批量并行不省钱；有沉淀跳过机制时批量可能更贵。
**审查问法**：S3 的开销预估算了吗、算得对吗？哪些调用可以被传统过滤或沉淀库跳过？

## ④ 沉淀 / 主链路解耦
识别结果沉淀（案例库、亮点库、prompt 长期记忆）走旁路，不阻塞主链路；沉淀反过来降低主链路开销。
**审查问法**：有没有把"写库/回流"做成主链路必经节点？

## ⑤ 人审兜底 + 案例回流
拿不准的必须有转人审出口（疑似态、低置信度）；人审结论回流为长期记忆/案例库。全自动无兜底的方案不许上。
**审查问法**：哪个节点输出会触发转人审？人审结论去哪了？
