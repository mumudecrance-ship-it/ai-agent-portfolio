# 图像文本基础能力

> 调用形态均为 http_request 节点。演示环境 mock 地址前缀 `http://127.0.0.1:8787`；生产环境由服务提供方提供正式地址与鉴权，仅 base URL 不同。

| 能力 | mock 地址 | 入参 | 返回口径 | 前置条件 |
|---|---|---|---|---|
| 同图识别 | `/mock/svc/same-image` | `{image_urls: []}` | `result`: 0非同图 / 1疑似 / 2同图 | 无 |
| AI生图识别 | `/mock/svc/ai-image` | `{image_urls: []}` | `result`: 0非AI / 1AI | 该商品需有客服标注的真实评价图 |
| 无关图识别 | `/mock/svc/irrelevant-image` | `{image_urls: []}` | `result`: 0相关 / 1疑似 / 2无关 | 该商品需 20 张以上标注相关图 |
| 敏感词检测 | `/mock/svc/sensitive-words` | `{text}` | `{hit: bool, words: []}` | 全公司统一，评价提交时已前置执行 |
| OCR | `/mock/svc/ocr` | `{image_desc/image_url}` | `{text}` | 无（商详图提卖点场景常用） |

## 使用口径

- 三态返回的 `1（疑似）` 统一处理为**转人审**，不自动定性——质量管控工作流的既有口径
- 同图/AI生图/无关图判定为低质量的前提差异：同图=直接打标无需复审；AI图/无关图=全部图片均命中才算低质量（有一张正常图不算）
- 敏感词与鉴黄暴恐属于公司级前置过滤，评价域工作流的入参默认是**已过敏感过滤**的数据；方案里不要重复设敏感词节点，除非处理的是工作流自产文本（生成的文案要出站前需过一遍）
- 逐条评价调图像接口是开销大户：先用传统判断（是否带图）过滤，再进接口
